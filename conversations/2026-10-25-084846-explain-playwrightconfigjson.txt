⏺ There's no playwright.config.json in this project. The config file is
  playwright.config.ts, written in TypeScript. Here's what each part does.

  import { defineConfig, devices } from "@playwright/test"

  defineConfig only gives you type checking and autocomplete. devices is
  Playwright's list of preset browser and device profiles.

  Where tests live and how they run

  Timeouts

  - timeout: 60_000: each test gets 60 seconds, including its hooks. The default
    is 30 seconds. Since the target is a remote Heroku site, which can be slow,
    the extra time makes sense.
  - expect: { timeout: 10_000 }: an auto-retrying assertion like await 
    expect(locator).toBeVisible() keeps retrying for up to 10 seconds before it
    fails. The default is 5 seconds.

  Reporters

  reporter: [['list'], ['html', { open: 'never' }]]
  - list prints one line per test in the terminal.
  - html writes a report to playwright-report/. open: 'never' keeps it from
    opening in a browser automatically. To view it, run npx playwright 
    show-report.

  use: settings shared by every test

  - baseURL: lets tests call page.goto('/login') instead of writing out the full
    URL. It defaults to http://the-internet.herokuapp.com. You can point it
    somewhere else with an environment variable, as the comment in the file
    says:
  BASE_URL=http://localhost:5000 npx playwright test
  - trace: 'on-first-retry': records a full trace (DOM snapshots, network,
    console, actions) only when a test is retried. Since retries only happen on
    CI, you'll only get traces there. Open one with npx playwright show-trace 
    <file>.
  - screenshot: 'only-on-failure': saves a screenshot when a test fails.
  - video: 'retain-on-failure': records a video of every test but keeps it only
    if the test fails.

  These files go into test-results/.

  projects: which browsers to test

  { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  { name: 'firefox',  use: { ...devices['Desktop Firefox'] } },
  { name: 'webkit',   use: { ...devices['Desktop Safari'] } },
  Every test runs once in each of the 3 browser engines. Each devices[...]
  preset sets the viewport, user agent and similar settings. To run in just one
  browser:
  npx playwright test --project=chromium

  In short

  Locally, tests run fast against the live Heroku site in 3 browsers, with no
  retries and the HTML report available when you want it. On CI (when the CI
  environment variable is set), the setup gets stricter: .only is blocked,
  failed tests are retried twice, 2 workers are used, and traces are captured
  for retried tests.

⏺ package.json describes the project to npm: its name, its shortcut commands,
  and the packages it depends on. There are two typos in it that you should fix;

  Project info

  "name": "internet-heruku-plat=ywright-practice",
  "version": "2.0.0",
  "private": true,
  - name: the project's identifier. ⚠️ It has a typo: plat=ywright should be
    playwright. Nothing breaks because of it, but it's worth fixing. (heruku is
    also spelled differently from "heroku", though it matches your folder name,
    so that may be on purpose.)
  - version: the project's version number, in semver format (major.minor.patch).
  - private: true: stops npm publish from publishing this to the npm registry by
    accident. This is standard for test projects.

  scripts: shortcut commands

  You run these with npm run <name>. npm test also works without run for the
  test script.

  Command: npm test
  Runs: playwright test
  What it does: Runs every test in all 3 browsers from your config
  ────────────────────────────────────────
  Command: npm run test:chromium
  Runs: playwright test --project=chromium
  What it does: Runs tests in Chromium only
  ────────────────────────────────────────
  Command: npm run test:headed
  Runs: playwright test --practice=chromium --headed
  What it does: ⚠️ Broken. --practice isn't a Playwright option, so this fails
  with an "unknown option" error. It should be --project=chromium. --headed
  opens a visible browser window so you can watch the tests run.
  ────────────────────────────────────────
  Command: npm run test:ui
  Runs: playwright test --ui
  What it does: Opens Playwright's interactive UI mode, where you can pick
  tests,
  watch them step by step, and see timelines
  ────────────────────────────────────────
  Command: npm run report
  Runs: playwright show-report
  What it does: Serves the HTML report from playwright-report/

  You don't need npx inside these scripts because npm automatically finds the
  playwright command in node_modules/.bin.

  devDependencies

  These are packages needed only while developing and testing, not at runtime.
  That's everything in a test-only project.

  - @playwright/test ^1.50.0: the test runner, assertions (expect), and browser
    automation API.
  - @types/node ^22.0.0: TypeScript types for Node built-ins. This is what lets
    process.env.CI in your config type-check.
  - typescript ^5.6.0: the TypeScript compiler, mainly used for editor type
    checking. Playwright runs .ts files itself, so you don't need to compile
    anything.

  The ^ (caret) means npm can install any newer minor or patch version within
  the same major version. For example, ^1.50.0 allows 1.50.0 up to, but not
  including, 2.0.0. The exact versions installed are recorded in
  package-lock.json.

  Two related notes

  - Running npm install doesn't download the browsers. After installing, or
    after upgrading Playwright, run npx playwright install once.
  - There's no "type": "module" field. That's fine, because Playwright handles
    the import syntax in your TypeScript files on its own.

❯ explain tsconfig.json

⏺ tsconfig.json sets up how TypeScript type-checks your code. Playwright doesn't
  use it to run anything: it transpiles your .ts files on its own and mostly
  ignores this file. So tsconfig.json mainly matters for your editor and for
  running tsc. There's also a path mistake in it that you should fix; it's
  marked below.

  compilerOptions

  Option: target
  Value: "es2025"
  Meaning: Which JavaScript version TypeScript compiles down to, and which
  built-in APIs it assumes exist (such as Array.prototype.findLast). Node 24,
  which you're on, supports ES2025, so this is fine.
  ────────────────────────────────────────
  Option: module
  Value: "commonjs"
  Meaning: Output uses require/module.exports. You can still write import in
  your
  source; TypeScript converts it. This matches the fact that package.json has
  no "type": "module".
  ────────────────────────────────────────
  Option: strict
  Value: true
  Meaning: Turns on all strict checks, including strictNullChecks and
  noImplicitAny. For example, page.locator('h1').textContent() returns string |
   null, so TypeScript makes you handle null. Keep this on.
  ────────────────────────────────────────
  Option: esModuleInterop
  Value: true
  Meaning: Lets you write import fs from 'fs' for CommonJS packages that have no

  real default export.
  ────────────────────────────────────────
  Option: skipLibCheck
  Value: true
  Meaning: Skips type-checking the .d.ts files inside node_modules. It's faster
  and avoids errors from conflicts between libraries' own type files.
  ────────────────────────────────────────
  Option: types
  Value: ["node"]
  Meaning: Loads only the @types/node global types (process, __dirname, and so
  on). Without this, TypeScript would load every @types/* package it finds.

  include

  "include": ["test/**/*.ts", "playwright.config.ts"]
  This lists the files TypeScript checks.

  ⚠️ Bug: your folder is called tests/ (plural), but this says test/. Right now
  tests/example.spec.ts isn't covered, so running tsc only checks the config
  file. Your editor still type-checks the spec file, but under default settings
  instead of this config. Change it to:
  "include": ["tests/**/*.ts", "playwright.config.ts"]

  Something I found while checking

  I ran npx tsc --noEmit and it passed with no errors. But TypeScript isn't 
  installed in node_modules, so npx downloaded TypeScript 6.0.2, not the ^5.6.0
  your package.json asks for. Running npm install will install the local copy,
  so tsc and your editor use the version you pinned. Also, because of the
  include bug, that check only covered playwright.config.ts.

  Useful command

  To type-check everything without writing any output files, which is a good
  habit before pushing:
  npx tsc --noEmit
  You could add it as a script in package.json, for example "typecheck": "tsc 
  --noEmit".

  before?
